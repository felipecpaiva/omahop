# v0.4 plan: second shortcut, app rules, hints

Goal (Felipe's standing instruction, 2026-11-06): finish the releases one by one; v0.4 follows v0.3. Source of ideas: BetterCmdTab (profiles, per-app rules, ignore-when-fullscreen, letter mappings) and Contexts (fast search), see `bettercmdtab-reference/features.md` and `competitive-analysis.md`. Everything stays a setting with a safe default, lives in the settings window, and tiling workspaces stay untouched by default.

## Scope

| # | Feature | Behaviour |
|---|---|---|
| 1 | **Same-app cycle** (the "profile" part) | A second shortcut (default `ALT + GRAVE`, the key above Tab) lists only the windows of the app you are in, like macOS Cmd+backtick. Same session, same overlay, same keys; the first press goes to the app's previous window. Setting `same_app_key` (text, empty turns it off). Generic user-defined profiles are NOT in v0.4 (a config-file-only feature would break the one-settings-window rule; they wait for a design that fits the window) |
| 2 | **App rules** | `windows.ignore_titles`: windows whose title contains one of these fragments are never listed (BetterCmdTab "title-fragment exclusions"). `windows.first`: apps always listed first (after the focused one is skipped as usual). All plain text settings, comma separated |
| 3 | **Pass-through for fullscreen apps** | `passthrough_fullscreen` (bool, default off): when the focused window is fullscreen, omahop steps aside and stock Alt+Tab runs (games, remote desktops, VMs want Alt+Tab). `passthrough` (apps, comma separated): the same for named app classes whatever their state. Out of scope for omahop means exactly stock behaviour, as everywhere else |
| 4 | **Hints** | `hints = off / numbers / apps`. With an empty query: `numbers` makes `Alt + 1` to `9` pick the n-th row (the overlay shows small numbers on the rows); `apps` uses `hint_keys` (text like `c=google-chrome, t=kitty`: pressing the letter with an empty query picks the most recent window of that app; the overlay shows the letter on the matching rows). A letter that is not mapped, or any key once a query exists, still types into the search, so search never breaks |

Not in v0.4: user-defined profiles, trackpad gestures, audio badges, anything that needs raw input.

## Design notes and traps

- **Where it lives:** pure logic in two new Lua modules (`rules.lua`: ignore titles, first apps, pass-through decision; `hints.lua`: parse `hint_keys`, number and letter jumps) with unit tests; the glue only wires them. The same-app profile is a filter over the list plus a second bind, so the session machine is unchanged.
- **Second bind:** `ALT + GRAVE` and `ALT + SHIFT + GRAVE`, unbound in stock; the free-chord snapshot (`binds.txt`) is checked like for the typing keys (a chord the user already uses is left alone). Needs a reload like `takeover`, because it decides which binds exist.
- **Pass-through** decides at the press (before anything opens), by asking Hyprland for the active window (`fullscreen` field, `class`); stock handler runs otherwise unchanged.
- **Hints vs search:** digits and mapped letters are hints only while the query is empty; once the user has typed a letter that is not a hint, everything types. The state file carries `hints=<mode>` and the overlay draws the hint on each row and card (small chip). A hint pick uses the existing `M.pick(index)`.
- **Settings in the window:** a new group "Rules" at the end (after "Peek strip") so earlier click positions stay valid; text fields for the lists, a switch for `passthrough_fullscreen`, buttons for `hints`.
- **Order of batches:** 10 rules and pass-through (pure, safest), 11 same-app cycle, 12 hints and overlay chips, 13 GIFs, notes, merge, tag, release.
