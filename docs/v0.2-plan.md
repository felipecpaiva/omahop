# v0.2 plan: cards, settings app, search

Goal (Felipe, 2026-11-06): after v0.1.0, build v0.2. Same quality bar as omagnet, same principles (no new icons by default, one settings app for everything,
slim but complete, learn from others and build our own way). Release plan row: "Looks and settings app".

## Scope

| # | Feature | Why now |
|---|---|---|
| 1 | Settings app (shell panel) for every v0.1 setting, live apply | Principle: every setting lives in the app. Every later feature adds settings, so this comes first |
| 2 | Cards style with window thumbnails (`style = "cards"`) | The DockDoor-like face Felipe asked for; thumbnails are verified to work (research/spikes.md S2 gaps below) |
| 3 | Type-to-search | Rivals have it (luwojtaszek, omaswitch); jump to a window by typing |
| 4 | Multi-monitor overlay | The overlay shows on the focused monitor today; verify and fix with real monitors |
| 5 | Close v0.1 leftovers | Hand checks: non-Qt apps for the Alt-menu fix, minimized restore, theme change, two monitors |

Not in v0.2 (stay in the roadmap): hover previews (v0.3), minimized/special polish beyond what the cards need, profiles and letter hints (v0.4).

## Open design questions (decide by evidence, record in decisions.md)

- **D14 search input.** The overlay is focusless and Lua polls keys (D5). Typing letters needs one of: (a) dynamic `ALT + <letter>` binds during a session (26 letters plus digits, registered only while a session is open), (b) a second entry point (for example `ALT + SPACE`) that opens a keyboard-grabbing overlay with a text field, like core's sticky mode and Contexts' search, (c) poll `hl.is_key_down` for letters each tick (no binds, works for 26 keys, but cannot tell the order of simultaneous keys and misses fast taps). Spike first: does (a) work with Alt held, do the letters leak to the app, what is the cost of 36 binds.
- **Cards layout.** Horizontal strip like DockDoor or a grid when there are many windows; thumbnail size from the screen; how many fit. Decide in batch 5 from real screenshots.
- **Live config apply.** Re-read on session open (cheap, no watcher) versus a file watcher. Read on open unless it is slow (measure).

## Risks

- Thumbnails of minimized or occluded windows may be blank or stale (not yet tested); mitigation: icon fallback on the card, snapshot taken when the session opens.
- Settings panel is a lot of QML: keep it one scrolling page like omagnet, built from the spec table, no per-setting code.
- The shell keeps plugin QML in memory: every QML change needs `omarchy restart shell` and closing the theme picker (gotchas.md). Budget for it in live tests.
