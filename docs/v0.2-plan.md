## Working rules for v0.2 (from the advisor review, 2026-11-06)

- **Branch `v0.2`.** `main` stays at v0.1.0. The installed plugin is a symlink to the working tree and `hyprland.lua` loads the Lua from it, so whatever branch is checked out is what runs on Felipe's daily Alt+Tab at the next reload or shell restart.
  Recovery if a half-done batch misbehaves: `git -C ~/Work/omahop checkout main && hyprctl reload && omarchy restart shell` (also in `gotchas.md`).
- **Reuse omagnet's own settings machinery.** Its `ConfigIO.js` (with its Node test), `SettingsStore.qml`, `SettingsPanel.qml` and the `.desktop`-installing `Service.qml` are ours (same author, MIT, same shell and look). Adapt them to omahop's keys instead of rewriting; the two plugins then look the same in the launcher and the panel.
  "Learn, do not copy" is about other people's code.
- **One spec, no drift.** `lua/config.lua` `C.spec` is the single definition. The panel reads a generated `spec.json`; `tests/run-all.sh` regenerates it with a `lua` one-liner and fails when the committed file differs.
- **Live run at the end of every batch** (`bash tests/run-all.sh`), not only at release.
- **Every tag ships with a feature highlight** (media, notes, GitHub release): `docs/releases/README.md`. v0.2.0 included.
- **Media kit** (brand concepts are in `branding/`): when Felipe picks a concept, build the full kit before v0.2.0 (icon set, README banner, social card, launcher icon for the panel).

## Open design questions (decide by evidence, record in decisions.md)

- **D14 search input.** The overlay is focusless and Lua polls keys (D5). Typing letters needs one of: (a) dynamic `ALT + <letter>` binds during a session (26 letters plus digits, registered only while a session is open), (b) a second entry point (for example `ALT + SPACE`) that opens a keyboard-grabbing overlay with a text field, like core's sticky mode and Contexts' search, (c) poll `hl.is_key_down` for letters each tick (no binds, works for 26 keys, but cannot tell the order of simultaneous keys and misses fast taps). Spike first: does (a) work with Alt held, do the letters leak to the app, what is the cost of 36 binds. Unbinding the chords at session end would delete a user's own bind on them (the S6 hole, times 36): take a snapshot with `io.popen("hyprctl binds -j")` when a session opens (about 5 ms; not at config load, which was the S6 risk) and only bind the free chords; the same snapshot, run once from a deferred timer after setup, also gives the stock-bind detection dropped in S6. For (b): while an overlay holds the keyboard Hyprland refuses to focus a window (core PR 16548 measured it), so the pick must be dispatched on `closelayer`.
- **Cards layout.** Horizontal strip like DockDoor or a grid when there are many windows; thumbnail size from the screen; how many fit. Decide in batch 5 from real screenshots.
- **Live config apply.** Re-read on session open (cheap, no watcher) versus a file watcher. Read on open unless it is slow (measure).

## Spike additions for the cards batch

S2 must cover `special:minimized` windows, occluded windows (likely blank: icon fallback on the card), 10 live views (CPU, frame rate), and L6 (a capture of a window whose monitor vanished aborts Hyprland: never create a `ScreencopyView` for a window whose output is gone).
S4 (pointer mask over the card for hover and click) is not part of v0.2: **cards are keyboard-only in v0.2**; hover and click arrive with v0.3 hover previews.

## Risks

- Thumbnails of minimized or occluded windows may be blank or stale (not yet tested); mitigation: icon fallback on the card, snapshot taken when the session opens.
- Settings panel is a lot of QML: keep it one scrolling page like omagnet, built from the spec table, no per-setting code.
- The shell keeps plugin QML in memory: every QML change needs `omarchy restart shell` and closing the theme picker (gotchas.md). Budget for it in live tests.
