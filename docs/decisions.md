# omahop decisions

| ID | Decision | Why | Status |
|---|---|---|---|
| D1 | Name `omahop`, plugin id `io.github.felipecpaiva.omahop` | omaswitch, omadock, omatab are taken in the marketplace and on GitHub; omahop is free on both (checked 2026-11-06) | decided |
| D2 | Public repo, MIT | Felipe's call, like omagnet. Scrub before every push (no LAN IPs, hostnames, home paths, client names) | decided |
| D3 | One repo, repo root is the plugin | Same as omagnet: `omarchy plugin add <git-url>` clones it, marketplace wants `manifest.json` at root | decided |
| D4 | `scope` is a setting: `floating` (default) or `all` | Felipe: default floating only, user free to extend. Stock behaviour must stay byte-for-byte on out-of-scope workspaces | decided |
| D4b | Window set is its own setting group, independent of scope: workspaces (`current`, `floating`, `all`) and monitors (`active`, `all`), default floating and active | Felipe: a user who limits hop to floating desktops should not see other windows; showing other monitors is a separate choice | decided, see `settings.md` |
| D10 | Positioning: floating-aware switcher (scope, filters, stock fallback, settings app, theme-live), not a plain Alt+Tab. Search moves to v0.2. Hover previews stay v0.3 but demoted | Competitive analysis: nobody has F12, F27 or a switcher GUI; vertical list and search already exist elsewhere | decided, see `competitive-analysis.md` |
| D11 | Product principles from omagnet: no new icons by default, one settings app for everything, slim and simple but complete (see `engineering-standards.md`). Consequence for D8: an own dock strip (option b) adds a new surface and is ruled out unless it is an opt-in setting; hover previews go through the stock dock (upstream hook) or an opt-in strip | Felipe, 2026-11-06 | decided |
| D12 | Engage upstream before building the switcher core: read core PRs #16548 and #16219, and decide whether to comment or offer scope, filters and raise handling as PRs | Both headline features are open core PRs with no maintainer reply; a merge makes our matching feature redundant | open, Felipe's call (commenting is outward-facing) |
| D5 | Lua owns keys and state (polling Alt and Tab with `hl.is_key_down`), QML draws a focusless overlay, and a harmless key (F24) is injected with `send_shortcut` so apps do not see an Alt tap | Evidence in `research/spikes.md`: S9 (release binds and global shortcuts miss the Alt release after another key, polling works), L1 (a consumed Tab makes a Qt app's menu bar take focus; the injected key prevents it). Fallback if the injection fails in common apps (GTK, Chromium, Electron): the overlay takes the keyboard on the first Tab | decided by evidence, re-check with the wider app list in batch 1 |
| D6 | Cards and list are both shipped, user picks | Felipe asked for both (DockDoor and Contexts styles) | decided |
| D7 | Take ideas, never GPL code | DockDoor, end-4, caelestia are GPL-3.0 | decided |
| D8 | Where hover previews live | Stock dock has no hook and a third-party plugin cannot reach its service or rebuild icon positions from outside (`v0.3-plan.md`) | **decided 2026-11-06: omahop's own opt-in peek strip** (`peek = off` by default, D11); core PRs 16219 and 16479 own stock-dock hover |
| D9 | Plugin or contribute to core | Core PR omacom/omarchy#16548 (Windows-style Alt+Tab, live thumbnails, all workspaces, MRU) is open. If it merges, a plain switcher is redundant. omahop's difference: floating-scope default, vertical list style, hover previews, settings app, theme-live | decided 2026-11-06: build omahop, grow it release by release (Felipe asked for a gradual roadmap); revisit if #16548 merges |

| D13 | Learn, do not copy: study others, keep the best ideas, avoid their mistakes, design our own structure. Quality bar is the omagnet level (gates in `lessons-from-others.md`) | Felipe, 2026-11-06 | decided |
| D14 | Search input: while a session is open, dynamic `ALT + <letter, digit, space, backspace>` binds (consuming, so letters never reach the app), only for chords the snapshot of `hyprctl binds` shows free; the snapshot is taken by a detached `hyprctl` after load, never synchronously | Spike (`research/spikes.md`): `io.popen("hyprctl binds")` freezes the desktop for 5 s; 38 binds register in under 10 ms; chords are unbound exactly at session end, so a user's own bind is never lost | decided, built and live-tested in batch 6 |
| D16 | `modifier` setting (`alt` default, `ctrl`; Super and Ctrl+Alt are not offered, Omarchy owns both Tab chords), one table in `lua/modifier.lua` (bind string, modmask, polled xkb keys, whether it replaces a stock bind). Pinned at load like `takeover`. Alt replaces Omarchy's Alt+Tab at once and runs it out of scope; Ctrl binds Tab after the snapshot only when it and its Shift variant are free, log the reason otherwise, and hand the key back to the app out of scope. `same_app_key` must start with the same modifier (not rewritten). Shift is not offered | Ctrl+Tab belongs to apps: it has a stock meaning omahop could run itself, so the D14 free-chord rule decides, and a used chord is reported instead of taken | decided 2026-11-07, built on branch v1.3-modifier, live checks pending |
| D18 | Icon pack zips: one shared rule set (`tools/pack-lib.sh`, sourced by index, export and import); export and import are strict (any file pack-index would skip refuses); the zip holds `pack.toml` and `icons/` only; bsdtar only, no `zip`/`unzip` fallback; the importer unpacks each checked entry itself (`bsdtar -xOq` by name, capped with `head -c`) instead of letting bsdtar write a tree; zip-bomb ratio is total unpacked size over the zip's file size; the folder is the pack.toml `name` folded to the `icon_pack` rule; staging under the cache dir, then a copy beside the packs and one rename | bsdtar is in libarchive, which pacman needs, so it is on every Arch system, while zip and unzip are optional; a second parser would be a second attack surface. Unpacking by checked name means a link, `..` or absolute path cannot be created even if a listing check had a hole, and the byte cap holds when the listing lies. `bsdtar -tv` shows no compressed size, so the ratio is per archive; the per-file caps bound the rest. Export uses an mtree list so no change time is stored and the same pack gives the same bytes | decided and built 2026-11-08 (branch v1.4-pack-zip) |
| D17 | Browser tabs (`browser_tabs`, off by default): ONE implementation, in Lua (`lua/tabs.lua` with a strict decoder `lua/json.lua`), not a `Tabs.js`. Tab rows are ordinary entries of the session list, after their window, carrying the window's address; the state file gains a `t` line (address, class, minimized, active, site, title) and QML only draws it (`TabRow.qml` in the list, an icon-only `CardItem` in cards). Tab rows show only while a search is typed. Files are read once per session at the first typed letter: `find` lists the folder (Lua has no readdir; not hyprctl, so no deadlock), at most 8 files of 1 MB. Return runs the detached `tools/omahop-tabs-activate` first, then the normal focus and raise; the glue never opens a FIFO. Flag and ignore files are made and removed by one idempotent script (`tools/omahop-tabs-files`) called from Lua (load, config change) and from `Service.qml` (at once from the settings window, off at unload) | Lua already owns the list, the selection, search (accent fold, fuzzy), hints and Return, and QML picks rows by index: tab rows built in QML would break that index contract and need a second search implementation. Rows only with a search keep Alt+Tab cycling, the quick tap, hints and action keys exactly as before (with 30 tabs open, Tab would otherwise walk through tabs), and a quick Alt+Tab costs no file read at all. A Lua JSON decoder (about 100 lines, tested with hostile input) is cheaper than a second copy of the matching and search rules. Spike: `research/tabs-spike.md`; contract: `file-contract.md` | decided and built 2026-11-08 (branch v1.4-tabs-omahop), live checks pending |
| D21 | Audio marker (`audio_marker`, off by default): a snapshot of `pactl -f json list sink-inputs` plus `ps -e -o pid=,ppid=`, taken by `tools/audio-sample.sh` once when the list opens and only with the setting on, matched to windows in a pure `AudioMarker.js` (pid, then up the parent chain at most 16 steps, nearest owner wins; then app binary or name against the class or its last dot part; else nothing). Playing means `corked` and `mute` both exactly false. The marker is the Nerd Font speaker U+F028 as text after the app name, in rows and cards, never on tab rows. The overlay owns it; no Lua or state file change. Not the live Quickshell PipeWire service | Zero idle cost by construction ("nothing runs while the switcher is closed"); `corked` and `mute` are plain fields; 3 ms for pactl and 5 ms for ps here. The live service would hold trackers on every stream while the setting is on, and Omarchy's own audio panel documents two shell crashes around PwNode properties and removed nodes. Stream titles stay in the pipe and in memory. Spike: `research/audio-spike.md`. D19 and D20 are unused numbers | decided and built 2026-11-08 (branch v1.5-audio), hand check pending |
| D20 | Swipe trigger (`swipe_trigger`, off by default): one `hl.gesture` with the `{ start, update, finish }` callback table, `direction = "horizontal"`, `swipe_fingers` 3 or 4 (default 4), registered at load only when the setting and `takeover` are on, once per Lua state. Each `swipe_distance` px of travel is one row (pure `lua/swipe.lua`); the first row opens the session through the same `open_session` as Alt+Tab, with no injected key; fingers down hold the session like the modifier; lift picks. Lift on the start window, `cancelled`, or 10 s with no gesture event close without switching. Out of scope and passthrough: nothing. Touchscreen: not offered. No config scan at load; `tools/gesture-map.lua` lists the gestures in use | `research/swipe-spike.md`: Hyprland 0.56.2 gives continuous Lua callbacks for touchpad swipes only, so lift is a real end event and no tap or timeout pick is needed. A clashing gesture is refused by Hyprland as a config error (not a Lua error) and cannot be listed at runtime, so omahop loads last and lets the user's gesture win; 3 fingers horizontal is the common workspace swipe, hence 4 | decided and built 2026-11-08 (branch v1.5-swipe), hand checks pending |
| D15 | `search_linger_seconds` (default 0): with a search typed, releasing Alt no longer picks; the list lingers, the overlay takes the keyboard (route B), Return picks, timeout and a click outside cancel | `research/linger-spike.md` (route B over bare-key binds: any character, crash-safe grab; click while Exclusive measured in its Result section). Default 0 keeps "release Alt picks" for everyone else | decided and built 2026-11-07 (branch v1.1b), two monitors not measured |
| D19 | Named profiles: `[profiles.<name>]` (and `.windows`, `.keys`) tables in the same `config.toml`, chosen by one top-level setting `profile` (default empty). Per setting the value in use is the profile's if valid, else the base, else the default; bad and refused profile values are logged. Not overridable: `reload` settings (takeover, modifier, same_app_key), `base_only` ones (browser_tabs, browser_tabs_ignore, profile) and hidden ones, as spec metadata (`C.overridable`, `overridable` in spec.json). One rule in two languages, `C.resolve` and `ConfigIO.resolve`, held equal by a parity test on shared fixtures. The settings window switches the profile (a choice row) and captions the rows it replaces, but does not edit a profile's values. Automatic choice and per-shortcut profiles are later steps | One file keeps one parser, one watcher and the line-preserving writer; a folder of profile files needs a directory listing Lua lacks. Settings read only at load would be silently ignored after a profile switch, so they are refused instead. Privacy settings stay in one place. Laying over the base (not the defaults) means a bad profile value never undoes a user's base choice. Editing profiles in the window would need a second mode for every row; switching covers the use case with no new widget. Spike: `research/profiles-spike.md` | decided and built 2026-11-08 (branch v1.5-profiles), live checks pending |

## Prior art summary (full table in `research/thumbnails-and-prior-art.md`)

- BetterCmdTab (rokartur, macOS, GPL-3.0, active) adds ideas: tap vs hold with a reveal delay, opt-in live config file, per-shortcut profiles, letter hints, per-app rules. Top 6 are in its reference file; fold the winners into ROADMAP phase 1 and 3.
- Marketplace already lists about 25 switcher, overview and dock plugins, several with live previews.
- Core dock exists (floating workspaces only), no previews, many open items.
- Pattern to copy: `omarchy-altswitch` (Lua for keys and state, QML renders the list, Alt release handled by a Lua submap).
- The research agents' notes on hyprshell, end-4 and caelestia behaviour come from prior knowledge, not from reading code.
