## #16548 Window switcher (rndaom, opened 2026-10-25, 12 commits, +1222/-119, 65 files, most are i18n)

New shell plugin `omarchy.switcher` (kind `service`, three QML and JS files, about 940 lines) plus two Lua files.

How it works (this is the technique worth learning):
- Binds: `ALT + TAB` and `ALT + SHIFT + TAB` go to `hl.dsp.global("omarchy:switcher.next"/"previous")` with `repeating = true`.
  `ALT_L` and `ALT_R` go to `omarchy:switcher.alt` with `ignore_mods = true, non_consuming = true`. The plugin's `GlobalShortcut` has
  `onReleased` = commit. So release is caught by a global-shortcut release, not by polling and not by a submap.
- The overlay maps on the FIRST Tab, before it is drawn (reveal delay 100 ms), so the keyboard leaves the app at once. Reason given:
  an app that saw Alt down and up with nothing between treats it as a tap of Alt and opens its menu bar. (This breaks our plan D5,
  a focusless overlay with Lua owning the keys. See discussion point 1.)
- While the overlay holds the keyboard, Hyprland refuses to focus a window. So the pick is dispatched on the `closelayer` event
  (`Hyprland.onRawEvent`), with a 500 ms fallback timer.
- Order: MRU kept from `activewindowv2` raw events, `closewindow` removes, `movewindowv2` into `special:minimized` demotes. Fallback to Hyprland
  `focusHistoryID` for windows not seen since shell start.
- List: ALL toplevels, every workspace and monitor, minimized included. It keeps only windows that have a Wayland toplevel (this removes Wine and Proton ghosts).
  Dialogs are grouped under their owner and come back on top.
- Activation: Lua `o.window_switcher.activate(addresses)`: for each window `hl.dsp.focus({window})` then `hl.dsp.window.alter_zorder({mode="top", window})`.
  A window on another workspace brings its workspace; a scratchpad window shows its special workspace; a minimized one is moved onto the active workspace
  (not when that workspace is a named one). This is the raise handling the community lacked: focus, then `alter_zorder top`.
- Extra: `foreground-lock.lua` turns `focus_on_activate` off for a fullscreen XWayland window once it loses focus (stops Proton games stealing focus back).
  `omarchy-shell omarchy.switcher open|next|previous` opens a sticky switcher for bindings with no Alt (IPC).
- Tests: `switcher-test.sh` covers order, first pick, wrap, removal while open, row layout, Up/Down (pure `SwitcherModel.js`, same idea as ours).
- Claims verified on live Hyprland 0.56.2, two monitors; Team Fortress 2 and Wizard101 under Proton for the game fix.

What it does NOT have: any setting or config, any scope or filter (all windows everywhere, always), floating awareness, search, a list style
(cards only: thumbnails with icon and title), per-monitor or per-workspace limits, ignore rules, a settings UI. It also removes the stock
"Reveal active window on top" bind and an unrelated `XF86Display` binding (bot flagged: restore it).
Open bot findings still plausible: dialog owner tracking, minimized order after shell restart, layout overflow with many windows (no scroll).

## #16219 Dock hover previews (itscallssh, opened 2026-10-21, +660/-39, 5 files)

Edits the core dock. Hover an app icon: after 350 ms a tooltip shows up to 4 live thumbnails (3 on a vertical dock), `ScreencopyView` with
`captureSource: card.active ? card.toplevel : null` (only the card in view is captured). Click focuses (restores a minimized window first),
the hovered one is highlighted, the focused one outlined, minimized ones dimmed, the dock stays revealed while hovering previews, a 40 ms
timer refreshes toplevels, and the surface reserves room so previews are not clipped. Open bot findings: translation keys, new-window launch scope, minimize switching workspaces.

## #16479 Dock window list (dedeanth, +262, 5 reviews, one change request)

Different answer to the same wish: up to three dots under each icon (one per window), hover 350 ms opens a text list (title and where it lives), click brings it forward.
A reviewer asked for a filled versus hollow dot for minimized windows. It is the more active PR (updated 2026-11-06). #16219 and #16479 compete.

## What this means for omahop

- The two headline features (switcher, hover previews) are each one core PR away from existing in core, in simple form, with no settings.
- Core's approach is a good template and a clean reference (MIT in an MIT project, with attribution if code is copied).
- The gaps stay open exactly where our decisions put us: scope (floating), window-set filters, settings, list style, per-app cycling, search.
- Technical facts to adopt or test: global-shortcut release for Alt (S9), overlay takes the keyboard on first Tab (conflicts with D5), pick on `closelayer`,
  raise via focus then `alter_zorder top` (S8), toplevel-only filter, dialog grouping, `focus_on_activate` lock for games.
