Goal (Felipe, 2026-11-06): finish the releases one by one, starting with v0.3. Same quality bar and principles (no new icons by default, one settings window, learn do not copy, flexibility, scalability, per-language standards, every tag ships GIFs and notes).

## D8 resolved: where hover previews live (evidence)

Researched on this machine (Omarchy 4.5.0-3):
- The stock dock (`omarchy.dock`) has no hook for plugins. A third-party plugin's shell facade (`PluginShellApi.serviceFor`) is limited to the plugin's own id ("ordinary plugins are limited to their own id"), so it cannot read the dock's items or positions.
- From outside, icon positions cannot be rebuilt: the dock layer is 1280x194 at the bottom (it reserves a popup area above the icons), the number and order of icons live in the dock's model (pins from config, running apps, a session drag order), and the slot size depends on font scale.
- Reaching into the shell's QML object tree is possible (the facade says it is not a sandbox) but would depend on first-party internals and reads as an attempt to defeat the plugin scoping: not done.
- Core PRs 16219 (hover live previews on the dock) and 16479 (window list on hover) are the right home for stock-dock hover previews; we do not touch them and do not comment (outward-facing).
Decision: omahop ships its own **peek strip**, strictly opt-in (`peek = "off"` by default, so nothing is added to the desktop unless the user turns it on, D11): a slim row of the running apps with window previews on hover. It does not replace the stock dock; it is for users who want DockDoor-style previews, with or without the stock dock.

## Scope

| # | Feature | Notes |
|---|---|---|
| 1 | Pointer on the switcher (list and cards): hover highlights, click picks, a close button on the hovered row or card | The overlay takes the pointer only over its card (input mask); a pointer resting where the card opens must never fight the keys: hover reacts to real movement only (core PR 16548 learned the same). Click calls Lua through `hyprctl eval` from QML |
| 2 | Quick actions | `Delete` closes the picked window while the list is up; the hover buttons close and minimize. Closing is a request (the app may prompt): the row stays until the window is gone |
| 3 | Peek strip (opt-in) | `peek = off / edge / always`, `peek_position = bottom / top / left / right`. `edge`: a thin hot edge reveals the strip when the pointer touches it, it hides when the pointer leaves. Icons grouped by app with a count; hover shows a popup with a card per window (the same `CardItem`), click focuses (restoring a minimized window), the hover buttons close and minimize. Only on floating workspaces by default (`scope` applies) |
| 4 | Settings | peek, position, hot edge size, close and minimize buttons on/off; all from the spec table, no panel code |

Not in v0.3: anything that replaces or patches the stock dock; per-app grouping rules (v0.4).

## Risks

- A layer-shell strip at a screen edge can steal clicks from the area under it: keep the hot edge thin (default 2 px) and the strip small; test that apps under the edge still get clicks when the strip is hidden.
- Pointer input on a surface that appears under a resting pointer: gate hover on movement.
- `hyprctl eval` from QML is fine (the freeze was Lua calling hyprctl); guard the argument (addresses are hex only) so nothing can end the Lua string.
